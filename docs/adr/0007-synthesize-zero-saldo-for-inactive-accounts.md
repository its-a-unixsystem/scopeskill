# Synthesize zero Saldo for inactive accounts

Scopevisio's **SuSa** endpoints (`/datasource/susa/*`) omit accounts that have no bookings or opening balance in the requested date range. When querying account balances via `sachkonto balance`, `debitor balance`, or `kreditor balance`, the **`sv-cli`** lazily verifies whether the account exists in master data upon a **SuSa** miss: if the account exists, the CLI synthesizes a zeroed **Saldo** record (all balance amounts set to `"0,00"` and account name populated) rather than returning an error. If the account does not exist in master data, the CLI returns a clear `<type> <number> not found` error.

This deviation from raw API passthrough is deliberate: in accounting, an existing account with no transactions during a period has an effective balance of zero. Emitting a zeroed **Saldo** record unblocks automated workflows verifying closing balances before period locks, while keeping the common path fast (a single **SuSa** call when activity exists) and strictly distinguishing non-existent accounts from inactive ones. Inspector commands (`show`) retain `null` for unposted **Saldo** periods to preserve visibility into whether an account was active.
